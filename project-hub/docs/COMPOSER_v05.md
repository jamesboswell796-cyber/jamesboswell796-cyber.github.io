# Project Hub v0.5 · 项目/方法提示词组装器

在原网站原目录新增 **＋ 组装提示词**，不另建网站或数据库。

## 用法
1. 原来的「新建 → 项目入口」用于录入真实项目，或录入 KH 成熟方法（例如标题 `K001｜PDF 保真优化`，入口填已核实的 KH 胶囊链接）。
2. 点击项目卡「组装」或顶部「＋ 组装提示词」；选择一个主项目、三种用途：临时参考 / 接手继续 / 组合设计。
3. 可把其它项目作为「借鉴项目」，或把 KH 方法入口作为「借鉴方法」，为每项填写一小句借鉴点。填写本次任务；预览自动更新。点击「复制完整提示词」。
4. 「☆ 收藏这个组合」保存动态引用记录。它与普通提示词共用 ID、记录修订、JSON 备份、编辑与云端批量事务。以后再次复制会重新查找当下项目的真实入口；若项目被删除或不再可用，**拒绝复制并提示修复**，不悄悄沿用旧地址。

## 范围与边界
- **一个主项目**；其他项目/方法只是局部参考。源链接及当前用户任务优先，绝不自动接管其他项目。
- 本轮不把 Portfolio 或 KH 的私人目录写进公开网站源码，也不会自动读取用户私有云盘；只有用户已录入或已导入的卡片可选。真正批量目录导入独立准备、审查后再做。
- KH 方法当前刻意复用 `kind: project` 的入口卡模型，而不是新造 `kind: method`、新数据表、公开固定目录。标题可使用 K001 等原标识，具体借鉴角色在组合时明确选择；这是低复杂度方案，不代表对方法做了全面 QA。
- 收藏组合内部序列化在 `kind: prompt` 的 `body` 中，前缀 `PROJECT_HUB_RECIPE_V1:`；导出 JSON 兼容旧结构。普通提示词仍按原行为处理。Notion 试验站未同步本机制，跨站导入组合将暂时被视为普通文本；不要用 Notion 站点管理动态组合。
- 云端尚未接通，不做未经许可的数据迁移。主站网页仍是 localStorage；本次没有使用 Supabase 管理密钥或增加后端。

## 验证 / 下一步
- 可使用 `node tests/composer-test.mjs` 测试纯组装器：三种用途、引用顺序、重复删除、动态收藏反序列化、来源失效、长度边界。
- 需要真实浏览器验证：主站搜索/草稿/编辑/备份/AI patch 回归、375px 移动端与 MenuBarX 窄窗口、剪贴板拒绝降级。GitHub Pages 构建成功 **不等于** 真实界面验收。
- 用户确认后，下一轮从 Portfolio PROJECT_MAP 与 KH LIBRARY_INDEX 定向核对候选，制作**私人**导入 JSON 并先预览，避免把学生/业务资料写入公开 GitHub。
