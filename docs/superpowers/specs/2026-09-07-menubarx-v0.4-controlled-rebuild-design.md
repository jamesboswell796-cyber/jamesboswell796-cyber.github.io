# MenubarX V0.4 Controlled Rebuild Design

## Purpose

Rebuild the MenubarX presentation and Markdown editing layer without replacing the proven persistence and safety layer. The product should behave first as a fast menu-bar copy shelf and second as a Markdown editor.

## Product priorities

1. **Fast retrieval and copy.** Opening the Menu Bar X window should expose recent/common notes immediately, with one-click full-note copy.
2. **Stable Markdown.** Markdown text is the canonical saved representation. Editing, saving, switching notes, closing, and reopening must not change structure unexpectedly.
3. **Compact reading.** In a roughly 430×600 window, typography must remain readable without desktop-scale headings or margins.
4. **Safe migration.** Existing IndexedDB records, note IDs, trash, snapshots, JSON import/export, backup files, and storage schema remain compatible.
5. **YAGNI.** V0.4 does not add images, tasks, folders, tags, cloud sync, or a larger Markdown dialect.

## Existing components retained

Retain `js/model.js`, storage repositories, IndexedDB web storage, backups, snapshots, export/import, service-worker offline support, note ordering, trash, and note-history behavior unless a small compatibility hook is required.

## Components replaced or reshaped

### Markdown core

The saved `note.body` remains Markdown source. The editor must not rely on lossy HTML-to-Markdown guessing as the source of truth.

V0.4 supports the existing compact dialect reliably:

- paragraphs and blank lines;
- H1/H2/H3 (`#`, `##`, `###`);
- unordered and ordered lists;
- blockquote;
- horizontal rule;
- bold, italic, inline code.

Incomplete block markers such as `#`, `##`, `###`, `>`, `-`, and `1.` must remain literal source until the user supplies the required separator/content. A saved document must round-trip deterministically.

### Editing model

Use a source-first editor mode. The visible editing control displays the Markdown source rather than mutating a `contenteditable` DOM tree and serializing the DOM back into Markdown.

A rendered reading view is generated from the Markdown parser. The reading view is never the canonical data source.

### Menu Bar X information architecture

The web runtime becomes a compact single-column flow:

- **Shelf view (default):** search, note list, full-note copy action, new-note action, settings.
- **Read view:** back, title, copy, edit, delete/overflow; rendered Markdown body.
- **Edit view:** back/cancel behavior, title, save status, compact formatting helpers, Markdown source editor.

The persistent desktop-style rail + drawer + editor split is no longer the default MenubarX shell.

### Copy behavior

Each shelf row exposes an explicit copy button. Copy uses the full Markdown source by default so prompts/templates preserve structure. The read view also exposes a primary copy action. Copy feedback is transient and does not navigate away.

### New note behavior

New note opens directly in edit mode with body focus. Title may remain `新笔记` until the user edits it; V0.4 does not introduce automatic title rewriting beyond existing model behavior.

## Typography

For MenubarX around 430×600:

- base reading text: 14–15px, line-height ~1.65–1.72;
- note title: 17–19px;
- H1: 20–22px;
- H2: 17–19px;
- H3: 15–16px;
- heading top/bottom margins compact enough that one heading does not consume a large fraction of the viewport;
- one neutral ink family; hierarchy is primarily size/weight/spacing, not separate heading colors.

The existing appearance color controls may remain for backward compatibility in data but are removed from the primary MenubarX experience.

## Responsive behavior

At widths <= 560px, there is no permanently visible notes drawer. Views occupy the full available width. No horizontal toolbar scrolling is required for primary operations.

## Data compatibility

No schema migration is required for existing notes. `note.body` is still a string containing Markdown. Existing JSON backups remain importable. Existing notes must display and edit without conversion on load.

## Cache/versioning

Bump the MenubarX runtime and service-worker cache version to `0.4.0`. README/version labels must agree. The service worker must invalidate the previous shell cache after activation.

## Verification requirements

Automated/browser tests must cover at least:

1. `## ` / `##` incomplete heading markers remain stable source and do not silently become a different structure after reload.
2. Complete H2 Markdown round-trips unchanged.
3. Multi-line pasted Markdown preserves every line and renders consistently immediately and after reload.
4. Soft/newline handling preserves Markdown source deterministically.
5. Shelf view is default at MenubarX startup.
6. Shelf-row copy copies the full body without navigating.
7. New note opens edit mode with body focus.
8. 430px-wide layout has no permanent drawer and no horizontal overflow for the main shell.

## Non-goals

No cloud sync, no account system, no rich-image blocks, no nested-list overhaul, no CommonMark-complete parser, no desktop Chrome-extension redesign beyond shared-code compatibility required by this change.
