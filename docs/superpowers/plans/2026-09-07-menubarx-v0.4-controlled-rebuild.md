# MenubarX V0.4 Controlled Rebuild Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the MenubarX desktop-derived shell and lossy rich-text editing path with a single-column copy shelf plus source-first Markdown read/edit views while preserving all existing local note data.

**Architecture:** MenubarX gets a dedicated `web/app.js` controller instead of importing the shared `js/editor.js` rich-editor application. It continues to use the existing model, IndexedDB storage, snapshot, backup, export, and Markdown rendering modules. Markdown source in `note.body` is canonical; a textarea edits it and `renderMarkdown()` renders a read-only view.

**Tech Stack:** Static HTML/CSS/ES modules, IndexedDB, existing model/storage modules, browser Clipboard API, browser File System Access API where supported.

**Spec:** `docs/superpowers/specs/2026-09-07-menubarx-v0.4-controlled-rebuild-design.md`

## Global Constraints

- Preserve existing IndexedDB database name `quickNotesMenubarX`.
- Preserve the current note/state schema and JSON backup compatibility.
- MenubarX runtime/service-worker/README version must be `0.4.0`.
- No images, tasks, folders, tags, cloud sync, or new Markdown dialect features.
- `note.body` Markdown source is canonical; rendered HTML is read-only output.
- Main shell must fit a ~430×600 Menu Bar X window without a permanent drawer.
